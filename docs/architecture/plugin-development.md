# CAD 插件扩展约定

## v1 边界

界面只处理规范化 JSON，不引用 COM 或厂商 SDK。Worker 持有真实会话和快照；客户端不能指定任意文件路径让服务修改。当前运行时仅注册 SolidWorks，无 Creo 或演示驱动；没有真实会话时不生成合成数据，不静默回退。

`adapters.py` 定义通用 `CadAdapter` 协议与 `CadPlugin` 描述符，`builtin_plugins()` 当前仅包含 SolidWorks。发现过程使用描述符中的进程/API 信息，Worker 通过同一注册信息创建适配器，避免发现与连接各自硬编码一套厂商列表。适配器提供 `snapshot`、`apply`、`close`；Worker 对外协调 `discover`、`connect`、`snapshot`、`apply`、`disconnect` 协议行为。未知 `cadId` 保守拒绝，不自动加载外部插件。

未来驱动须显式增加插件描述符与适配器，并先确认具体产品、版本、SDK 及分发授权。允许增加 C#/Java/C++ 工作进程，不把所有 SDK 强制塞进 Python。通用设计不是对未来任何 CAD 的支持承诺。

## 身份与作用域

文件名不是模型身份。路径、内部对象、配置/族表及属性域按厂商规则组合为不透明modelId；装配实例使用单独occurrenceId。UI不可解析modelId生成磁盘路径。遇到虚拟组件、未加载组件及族表实例必须明确标记支持范围。

## 能力与错误

软件版本、API可用性、文档状态和属性状态决定能力。未知能力默认为禁用；不要catch所有错误后假装成功。返回可理解的限制原因并记录SDK异常。

## 写回

1. 复核会话和文档身份。
2. 整批预检目标、重复项、原值、类型、只读和已有dirty状态。
3. 确认文件备份可用。
4. 按文档编排属性修改和保存，避免同文件不同属性互相触发dirty误拒绝。
5. 逐项报告写入/保存/核对；内存重读不是重开验证。
6. 保存状态未知不能自动重试。多文档部分失败需显式返回，不宣称事务回滚。

## 新驱动验收

必须测试未知模型、重复项、原值冲突、只读、dirty文档、多实例、文档切换、保存失败和断线；真实集成只使用工作副本。未验证的版本不列为支持。插件首次发布随应用统一打包，暂不动态加载任意外部脚本。
